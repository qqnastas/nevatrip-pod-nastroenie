# Промпт для Claude Code: «Под настроение» для nevatrip.ru

## Контекст

Я продакт в Неватрипе (nevatrip.ru). Это агрегатор: продаем чужие прогулки, экскурсии, автобусные туры, билеты в музеи и аренду теплоходов в Петербурге. В каталоге 200+ позиций, часть из них сезонные. Сейчас зима: воды мало, зато много новогодних, автобусных и музейных.

Хочу сделать дополнительный вход в каталог для тех, кто не знает, что выбрать. Человек свайпает карточки с настроениями, как в Тиндере (вправо «хочу», влево «мимо», вверх «обязательно»), и получает три подходящие прогулки с процентом совпадения и строкой «Совпало: ...». В конце генерируется билет для сторис в стиле Letterboxd, который называет не человека, а его вечер: «Вечер на воде», «Петербург с легендами» и так далее. Фильтр в каталоге остается как есть, это отдельный инструмент рядом с ним.

К промпту прикладываю рабочий прототип `index.html`. Логику, тексты карточек, теги и скоринг бери оттуда. Дизайн оттуда не бери, он черновой.

## Как работаем

1. Сначала включи plan mode. Ничего не пиши в коде, пока мы не договоримся о плане.
2. Начни с исследования источника данных (раздел «Данные» ниже) и вернись ко мне с выводами и вариантами.
3. Задавай вопросы, если чего-то не хватает. Не придумывай факты о прогулках: цены, длительность, описания и статус берутся только из данных сайта.
4. Работаем маленькими шагами, после каждого шага коротко пиши, что сделал и что проверить.

## Данные: главное требование

Нельзя рекомендовать прогулки, продажи которых закрыты. Данные должны обновляться сами, без ручной работы.

**Шаг 0, исследование.** Фронт nevatrip.ru сделан на Next.js, картинки лежат на static.nevatrip.ru. Посмотри сетевые запросы на страницах каталога (например, /novogodnie-ekskursii, /avtobusnye-ehkskursii, /muzei, /day/...) и найди, откуда фронт берет карточки: API, JSON Next.js, sitemap. Мне нужно понять:
- есть ли в данных признак активности: ближайшая дата рейса, наличие расписания, статус, тег «Сезон закончился» (у нас он ставится на закрытые страницы);
- можно ли получить весь каталог одним или несколькими запросами;
- какие поля доступны: название, url, цена, длительность, категория, картинка.

Отдельно подготовь короткий текст запроса к нашему техотделу: какой эндпоинт нам нужен и с какими полями. Если официальный API есть или его быстро сделают, используем его. Парсинг сайта только как запасной вариант.

**Архитектура данных, как я ее вижу** (предложи лучше, если видишь):
- Автоматические данные (название, цена, длительность, картинка, активность) тянутся с сайта по расписанию: GitHub Actions или Vercel Cron раз в сутки, лучше чаще. Результат сохраняется в `catalog.json`. Запрос идет на сервере, а не из браузера пользователя.
- В выдачу попадают только активные позиции: есть ближайшая дата и нет тега «Сезон закончился». Если статус определить нельзя, позиция не показывается.
- Ручные данные, то есть теги настроений, хранятся отдельно и привязаны к url прогулки. Удобнее всего Google-таблица (url → теги), чтобы я могла править теги без программиста. При сборке теги склеиваются с автоматическими данными.
- После каждого обновления скрипт пишет отчет: какие активные прогулки остались без тегов (они не участвуют в подборе, пока я их не разметила) и какие теги указывают на прогулки, которых больше нет в каталоге.
- Если обновление упало, остается последняя рабочая версия каталога, а мне приходит уведомление (например, issue в GitHub).
- Проверка на клиенте: если у прогулки в момент показа нет ближайшей даты, она не попадает в топ-3.

Набор карточек-настроений зависит от сезона. Сейчас зимняя колода из 12 карточек в прототипе. Летом будут закаты, развод мостов, открытая палуба, Финский залив. Колоды лежат в конфиге, переключаются по датам, и я могу добавить новую без правки логики.

## Дизайн: хочу красиво, а не базово

- Подключи Figma MCP. Вот UI-кит Неватрипа: [ССЫЛКА НА UI-КИТ]. Используй его как библиотеку: цвета, шрифты, радиусы, кнопки, карточки, иконки. Сам UI-кит не трогай и ничего в нем не меняй.
- Если будешь делать макеты в Figma, создавай отдельный файл в команде Неватрипа.
- Используй скиллы для фронтенда и UI-ревью (frontend-design, ui-review или аналоги, которые есть). После каждого экрана делай скриншот и проверяй сам, прежде чем показывать мне.
- Настроение: зимний вечерний Петербург, огни, лед, уют. Выглядит как модный продукт из рилс продакт-билдеров: смелая типографика, плавные анимации свайпа, тактильность. Но без кринжа и без лишних эмодзи.
- Mobile first. Основной трафик с телефонов, свайп должен ощущаться нативно.
- На карточках прогулок в результате используй настоящие фото с static.nevatrip.ru. Для карточек-настроений подбери фото из каталога или сделай генеративную графику, но лучше, чем в прототипе.
- Билет для сторис: формат 9:16, кнопки «Поделиться» (Web Share API, где поддерживается) и «Сохранить картинку».
- Доступность: фокус с клавиатуры, стрелки для свайпа, prefers-reduced-motion.

## Тон текстов

Это самое важное после данных. Молодым продукт делает механика: свайп, билет, шеринг. Тексты при этом спокойные и короткие, как у Letterboxd или итогов года в Spotify.

- Обращаемся на «ты».
- Никакого сленга, которым бренд пытается казаться молодым: «вайб», «зашло», «кайф», «It's a match», «краш», англицизмы. Это кринж, и его сразу видно.
- Не называем человека типажами вроде «Главный по праздникам» или «Мастер на все руки». Называем вечер или формат.
- Объяснение подбора не предложением, а фактом: «Совпало: огни города, ужин с видом».
- Короткие фразы, без восклицательных знаков, без рекламного восторга и без эмодзи в текстах.
- Все тексты интерфейса из прототипа уже переписаны в этом тоне, бери их как образец. Если пишешь новый текст, сначала покажи его мне.
- Без буквы «ё».

## Логика из прототипа (сохранить)

- Свайп вправо +1, вверх +2, влево −1 к тегам карточки. Совпадение считается косинусной близостью вектора предпочтений и тегов прогулки.
- Объяснение «почему» собирается из тегов, которые человек лайкнул и которые есть у прогулки.
- Если все свайпы влево, показывается экран «Сегодня ничего не зацепило» со ссылкой на каталог.
- Название вечера для билета: «Вечер на воде», «Новогодний Петербург», «Петербург с легендами», «Дворцы и интерьеры» и другие из прототипа.

## Аналитика

Нужен счетчик Яндекс Метрики и цели на каждый шаг: `vibe_start`, `vibe_swipe` (карточка и ответ), `vibe_result`, `vibe_no_match`, `vibe_click_item` (позиция в топе и url), `vibe_ticket`, `vibe_share`. В ссылки на сайт добавь UTM, чтобы в Метрике Неватрипа были видны продажи, пришедшие из этого инструмента. ID счетчика спроси у меня.
